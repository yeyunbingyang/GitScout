# GitScout 开发实施计划

- 产品：GitScout · 开源项目发现与研究平台
- 计划版本：v1.0
- 技术基线：React + FastAPI + SQLite
- 运行模式：Windows 本地 Web 工作台

## 1. 实施目标

以 GitScout v0.5.1 需求说明书和 HTML 原型为产品基线，交付可在 Windows 本机运行的 Web 工作台。首期实现真实 GitHub 采集、SQLite 历史快照、Stars 总榜、推荐、感兴趣项目和研究工作区。

## 2. 范围约束

### 首期建设

- React + TypeScript + Vite 前端。
- Python + FastAPI 后端。
- SQLite 唯一业务数据库，使用标准库 sqlite3。
- Python asyncio 进程内任务调度。
- Trending 日 / 周 / 月采集和历史快照。
- Stars 总榜独立采集、分片和完整性提示。
- 趋势总览、周期榜单、Stars 总榜、周期比较、推荐、兴趣和研究页面。
- Windows 启动脚本、日志、备份和恢复。

### 不纳入首期

PostgreSQL、Redis、Celery、Docker、微服务、多用户权限、远程公网访问、桌面壳和 AI 自动源码研究。

### M2 · Trending 真实采集与调度（代码已提交，CI 验证待确认）

- 服务重启时将遗留运行任务标记为 interrupted。
- 周期榜单历史查询 API、服务端筛选 / 排序 / 分页。
- 前端周期榜单、采集记录、调度设置页面接入真实 API。
- 增加 HTML Fixture、快照持久化、调度计算和 API 集成测试。

本阶段页面中的采集状态明确标记为等待接入；当前没有把模拟数据当成真实 GitHub 采集结果。

## 5. 后续详细任务

### M2 · Trending 采集

已提交实现：HTTPX 请求客户端、BeautifulSoup 解析器、仓库主档 Upsert、独立快照、任务记录、重试和本地 asyncio 调度；前端已接入周期榜单、采集记录和调度配置。

待验收：GitHub Actions 全量测试通过；在用户本机实际运行日 / 周 / 月采集；确认 GitHub 当前页面结构解析正确；验证自动调度触发、失败恢复与历史快照回查。

验收：日 / 周 / 月独立采集；历史快照不可覆盖；失败批次不标记成功；自动计划按各自时区运行。

### M3 · Stars 总榜（实现已提交，CI 与 Windows 本机验收待确认）

- GitHub Search Repositories API，按 Stars 降序采集公开仓库。
- 默认 Top 5,000 / 最低 100 Stars；支持 Top 1,000 / 3,000 / 5,000 / 10,000。
- Stars 数值区间递归分片；同 Stars 桶超限时按创建日期继续拆分。
- 按 GitHub Repository ID 去重，更新仓库主档、Topics 和 Stars 历史采样。
- 每次扫描保存独立历史快照、分片记录、incomplete_results 和覆盖说明。
- 支持手动扫描、失败 / 部分成功重试和 Stars 每日自动计划。
- 前端 Stars 总榜、历史扫描、分片覆盖详情、采集任务和设置页面已接入真实 API。
- 已增加 Stars collector、持久化、API 和调度配置测试。

验收：Search API 分片不超过 1,000 条结果窗口；高 Stars 分片优先；部分分片失败或 incomplete_results 必须明确标记；历史扫描不可覆盖；不得将 Top-N 榜单称为 GitHub 全站完整仓库清单。

### M4 · 榜单与趋势分析（CI 已通过，Windows 本机验证待确认）

- 趋势总览：项目库总量、当前周期收录数、新晋上榜、跨周期热门项目。
- 周期切换：日 / 周 / 月独立展示最新与上一批快照。
- 最近 12 次快照的平均 Stars 走势；当前周期语言分布和热门 Topics。
- 跨周期热门矩阵：基于日 / 周 / 月各自最新快照 Top 100，展示对应排名。
- 最新 Stars 扫描时间、覆盖数量和榜首仓库信息。
- 历史快照比较：选择同周期两个不同批次，计算新增、掉榜、排名上升、下降和不变。
- 比较支持关键词、语言、变化类型筛选、分页和完整结果 CSV 导出。
- 项目详情：仓库主档、Topics、个人兴趣 / 研究状态、日周月最佳排名与当前连续上榜次数、周期排名走势、Trending 历史、Stars 扫描历史和 Stars 观测走势。
- 从趋势总览、Trending 榜单、Stars 总榜和项目库进入项目详情。
- 新增 dashboard analytics、comparison、repository detail API 和对应集成测试；复用现有 SQLite 表，不新增数据库迁移。

验收：核心页面全部使用真实 SQLite 数据；查看历史快照不重新触发 GitHub 请求；比较仅接受同周期有效快照；缺失排名明确表示未进入该次采集范围，而非热度为零。

### M5 · 推荐引擎（CI 已通过，Windows 本机数据验证待确认）

严格遵循 PRD v0.5.1 第 16 节默认权重：

- Stars：30%
- 日榜：15%
- 周榜：30%
- 月榜：25%

- 候选池：最近一次成功 Stars 扫描 + 评分窗口内成功日 / 周 / 月快照的去重并集。
- 权重预设：综合平衡 30 / 15 / 30 / 25、趋势发现优先 20 / 25 / 35 / 20、长期价值优先 40 / 10 / 25 / 25。
- Stars 使用候选池百分位；日榜 30 次、周榜 12 次、月榜 12 次成功快照计算上榜比例。
- 最低有效样本：日榜 10、周榜 4、月榜 3；不足时保存 N/A，并按有效权重重新归一化。
- 保存算法版本、实际权重、数据窗口、候选数量、数据截止时间、子分、总分、排名、理由码和样本覆盖；每次计算创建新批次。
- API：权重预设、创建推荐批次、最新结果、历史结果、类别 / 关键词筛选与分页。
- 前端：权重预设切换、历史批次选择、优先关注 / 新兴潜力 / 长期稳定筛选、关键词 / 语言 / 主要贡献维度筛选、推荐理由、数据过期 / 不完整提示和 CSV 导出。
- 推荐分等级、并列排序和类别阈值按 PRD v0.5.1 固化，不将热度分数解释为质量分数。

验收：同一数据、算法版本和权重可复现同一结果；新计算批次不覆盖旧结果；不足样本不按 0 分处理；失败或部分成功快照不进入有效分母。

### M6 · 兴趣与研究（GitHub Actions CI 已通过）

- 新增 /api/v1/interested 与 /api/v1/research 路由；复用 0001 初始 schema 中的 interested_projects、research_projects、research_notes、research_tags 和 research_project_tags 表。
- 新增 0005_workspace_indexes.sql，为兴趣列表、研究状态 / 优先级、笔记和标签查询添加索引。
- 感兴趣 API：列表、详情、幂等标记、标签 / 备注 / 来源更新、取消标记；支持关键词、语言、标签、研究成员筛选、排序和分页。
- 研究 API：列表、创建、详情、部分更新、移出研究；支持状态、优先级、研究目标、下一步行动、结论、标签替换和研究笔记 CRUD。
- 状态规则：创建时默认待研究 / 中优先级；进入研究中或已完成时记录 started_at；完成时记录 completed_at；重新打开时清除完成时间并保留开始时间。
- 感兴趣和研究关系独立；同一仓库仅允许一条研究主记录，重复添加返回冲突；移出研究不会删除兴趣标记或仓库历史。
- Trending、Stars、推荐和项目详情行增加快捷标记 / 加入研究操作。
- 感兴趣页面支持项目库搜索添加、研究成员筛选、标签 / 备注编辑、CSV 导出。
- 研究页面支持项目库搜索添加、状态 / 优先级 / 标签筛选、目标 / 下一步 / 结论编辑、研究标签维护、多条笔记新增 / 编辑 / 删除和完整 CSV 导出。
- 项目详情响应聚合兴趣标签、研究标签和笔记数量。

验收：服务重启后收藏和研究数据仍然存在；取消兴趣不删除研究记录；重复加入不产生重复记录；笔记、标签和状态修改均可回读。

### M7 · 本地交付（后端 / 前端 / Windows CI 已通过）

#### Windows 启动与运行

- setup_gitscout.bat / scripts/setup_gitscout.ps1：检查 Python 3.11、Node.js 20+；创建 backend/.venv；安装依赖；构建 React；创建 .env 和本地目录。
- start_gitscout.bat / scripts/start_gitscout.ps1：首次运行自动初始化；检查端口冲突；隐藏后台启动 Uvicorn 单 Worker；轮询健康检查；成功后打开浏览器。
- stop_gitscout.bat / scripts/stop_gitscout.ps1：校验 PID 和进程命令行后停止服务，不按端口强制杀进程。
- 标准输出 / 错误输出写入 .runtime/logs；日志超过约 20 MB 时轮转，保留最近 10 组。

#### SQLite 备份与恢复

- backup_manager.py 使用 sqlite3.Connection.backup 在线备份，纳入 WAL 已提交数据；备份临时文件校验通过后再原子重命名。
- 自动备份默认启用，每 24 小时检查一次；服务启动时补做逾期备份，运行期间每小时检查；默认保留最近 14 份自动备份。
- 手动备份、恢复前安全备份不受自动保留策略清理。
- 备份支持列表、下载、SQLite integrity_check、schema_migrations 检查、删除。
- 恢复采用延迟执行：校验目标备份、先创建 pre-restore 安全备份、写入 restore_pending.json；下次启动在数据库初始化和调度器启动之前恢复，再执行迁移。
- 恢复目标只能从受控 backups 目录选择，不接受用户任意路径；待恢复文件不可删除。

#### 系统设置与文档

- 新增 /api/v1/system，提供系统信息、备份策略和备份管理 API。
- 新增 /system 页面，展示版本、Schema、数据库大小、数据路径、Token 配置状态、自动备份策略和备份历史。
- GitHub Token 只显示是否配置，不返回明文；数据目录修改仍通过 .env 手动配置，避免 UI 修改路径时误迁移数据。
- 新增 Windows 运维手册，更新 README、目录与运行约定。

验收：

- 自动化：备份 / 校验 / 下载 / 删除 / 恢复队列 / 启动恢复、自动备份间隔与保留策略均有测试。
- Windows：首次初始化、启动健康检查、重复启动、停止、日志轮转、手动备份和恢复演练。
- 端到端：启动 → 采集 → 推荐 → 感兴趣 → 研究 → 手动备份 → 停止 → 恢复 → 再启动 → 数据一致。
- 安全：监听地址为 127.0.0.1；Token 不出现在 API 响应；路径穿越不能读取或删除备份目录之外的文件。
