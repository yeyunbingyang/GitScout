# GitScout 开发实施计划

- 产品：GitScout · 开源项目发现与研究平台
- 计划版本：v1.0
- 技术基线：React + FastAPI + SQLite
- 运行模式：Windows 本地 Web 工作台

## 1. 实施目标

以 GitScout v0.5.1 需求说明书和 HTML 原型为产品基线，交付可在 Windows 本机运行的 Web 工作台。首期实现真实 GitHub 采集、SQLite 历史快照、Stars 总榜、推荐、感兴趣项目和研究工作区。

## 2. 范围约束

### 首期建设

- React + TypeScript + Vite 前端。
- Python + FastAPI 后端。
- SQLite 唯一业务数据库，使用标准库 sqlite3。
- Python asyncio 进程内任务调度。
- Trending 日 / 周 / 月采集和历史快照。
- Stars 总榜独立采集、分片和完整性提示。
- 趋势总览、周期榜单、Stars 总榜、周期比较、推荐、兴趣和研究页面。
- Windows 启动脚本、日志、备份和恢复。

### 不纳入首期

PostgreSQL、Redis、Celery、Docker、微服务、多用户权限、远程公网访问、桌面壳和 AI 自动源码研究。

## 4. 当前已完成：M0 / M1 / M2 第一批

- 建立 React + TypeScript + Vite 工程。
- 建立左侧导航和页面骨架，保留单一周期榜单导航。
- 建立 FastAPI 应用、健康检查、首页概览和项目库读取 API。
- 建立 SQLite 连接工厂和初始 SQL 迁移。
- 建立项目、Trending、Stars、推荐、兴趣、研究、采集任务和系统设置相关表。
- 配置 SQLite WAL、外键、busy_timeout 和基础索引。
- 建立数据库迁移、幂等约束测试。
- 增加 Windows 本地启动脚本。

### M2 · Trending 真实采集与调度（代码已提交，CI 验证待确认）

- HTTPX Trending 页面客户端，支持网络超时、429 和 5xx 重试。
- BeautifulSoup 解析日 / 周 / 月仓库卡片和周期 Stars 增量。
- 仓库主档 Upsert、Topics 同步、重复项目去重。
- 每次采集写入独立 Trending 快照，保留原始排名。
- 采集任务队列状态、运行日志、失败快照和失败原因。
- 失败 / 部分成功任务可重试，重试记录关联原任务。
- asyncio 本地调度循环；日 / 周 / 月独立启停、时区和执行时间设置。
- 服务重启时将遗留运行任务标记为 interrupted。
- 周期榜单历史查询 API、服务端筛选 / 排序 / 分页。
- 前端周期榜单、采集记录、调度设置页面接入真实 API。
- 增加 HTML Fixture、快照持久化、调度计算和 API 集成测试。

本阶段页面中的采集状态明确标记为等待接入；当前没有把模拟数据当成真实 GitHub 采集结果。

## 5. 后续详细任务

### M2 · Trending 采集

已提交实现：HTTPX 请求客户端、BeautifulSoup 解析器、仓库主档 Upsert、独立快照、任务记录、重试和本地 asyncio 调度；前端已接入周期榜单、采集记录和调度配置。

待验收：GitHub Actions 全量测试通过；在用户本机实际运行日 / 周 / 月采集；确认 GitHub 当前页面结构解析正确；验证自动调度触发、失败恢复与历史快照回查。

验收：日 / 周 / 月独立采集；历史快照不可覆盖；失败批次不标记成功；自动计划按各自时区运行。

### M3 · Stars 总榜（实现已提交，CI 与 Windows 本机验收待确认）

- GitHub Search Repositories API，按 Stars 降序采集公开仓库。
- 默认 Top 5,000 / 最低 100 Stars；支持 Top 1,000 / 3,000 / 5,000 / 10,000。
- Stars 数值区间递归分片；同 Stars 桶超限时按创建日期继续拆分。
- 按 GitHub Repository ID 去重，更新仓库主档、Topics 和 Stars 历史采样。
- 每次扫描保存独立历史快照、分片记录、incomplete_results 和覆盖说明。
- 支持手动扫描、失败 / 部分成功重试和 Stars 每日自动计划。
- 前端 Stars 总榜、历史扫描、分片覆盖详情、采集任务和设置页面已接入真实 API。
- 已增加 Stars collector、持久化、API 和调度配置测试。

验收：Search API 分片不超过 1,000 条结果窗口；高 Stars 分片优先；部分分片失败或 incomplete_results 必须明确标记；历史扫描不可覆盖；不得将 Top-N 榜单称为 GitHub 全站完整仓库清单。

### M4 · 榜单与趋势分析（实现已提交，CI 验收中）

- 趋势总览：项目库总量、当前周期收录数、新晋上榜、跨周期热门项目。
- 周期切换：日 / 周 / 月独立展示最新与上一批快照。
- 最近 12 次快照的平均 Stars 走势；当前周期语言分布和热门 Topics。
- 跨周期热门矩阵：基于日 / 周 / 月各自最新快照 Top 100，展示对应排名。
- 最新 Stars 扫描时间、覆盖数量和榜首仓库信息。
- 历史快照比较：选择同周期两个不同批次，计算新增、掉榜、排名上升、下降和不变。
- 比较支持关键词、语言、变化类型筛选、分页和完整结果 CSV 导出。
- 项目详情：仓库主档、Topics、个人兴趣 / 研究状态、日周月最佳排名、Trending 历史、Stars 扫描历史和 Stars 观测走势。
- 从趋势总览、Trending 榜单、Stars 总榜和项目库进入项目详情。
- 新增 dashboard analytics、comparison、repository detail API 和对应集成测试；复用现有 SQLite 表，不新增数据库迁移。

验收：核心页面全部使用真实 SQLite 数据；查看历史快照不重新触发 GitHub 请求；比较仅接受同周期有效快照；缺失排名明确表示未进入该次采集范围，而非热度为零。

### M5 · 推荐引擎

严格遵循 PRD v0.5.1 第 16 节默认权重：

- Stars：30%
- 日榜：15%
- 周榜：30%
- 月榜：25%

实现百分位和上榜频率、有效样本门槛、缺失指标 N/A 与可用权重重新归一化、推荐理由、权重预设、算法版本及推荐历史。不得擅自改变评分口径。

验收：同一数据、算法版本和权重可复现同一结果；新计算批次不覆盖旧结果。

### M6 · 兴趣与研究

- 从榜单、推荐和项目详情标记 / 取消感兴趣。
- 感兴趣标记不自动创建研究记录。
- 项目可单独加入研究工作区，且不可重复加入。
- 支持待研究、研究中、已完成、暂缓。
- 支持优先级、研究目标、下一步行动、结论、笔记和标签。

验收：服务重启后收藏和研究数据仍然存在；取消兴趣不删除研究记录。

### M7 · 本地交付

- Windows 环境检查和启动入口。
- 日志轮转、异常提示和 Token 安全。
- SQLite 安全备份、恢复和 integrity_check。
- 完成前后端单元测试、API 集成测试和关键用户流程测试。
- 更新 README、安装教程和常见问题。

## 6. 测试策略

- 数据库：迁移幂等、唯一约束、外键、事务回滚、WAL。
- API：健康检查、分页、筛选、空状态和错误响应。
- Trending：HTML Fixture、字段缺失、解析异常和快照写入。
- Stars：限流、超时、分片失败、去重和 incomplete_results。
- 推荐：权重、窗口、样本不足、缺失值和结果复现。
- 前端：导航、加载、空状态、错误状态、历史选择和研究交互。
- 端到端：启动 → 采集 → 查历史 → 推荐 → 收藏 → 研究 → 重启 → 数据仍在。

功能只有在需求编号明确、前端接入真实 API、后端逻辑完成、SQLite 持久化完成、异常状态完整、测试通过、文档更新并提交 GitHub 后，才标记为完成。
