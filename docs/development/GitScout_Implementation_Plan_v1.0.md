# GitScout 开发实施计划

- 产品：GitScout · 开源项目发现与研究平台
- 计划版本：v1.0
- 技术基线：React + FastAPI + SQLite
- 运行模式：Windows 本地 Web 工作台

## 1. 实施目标

以 GitScout v0.5.1 需求说明书和 HTML 原型为产品基线，交付可在 Windows 本机运行的 Web 工作台。首期实现真实 GitHub 采集、SQLite 历史快照、Stars 总榜、推荐、感兴趣项目和研究工作区。

## 2. 范围约束

### 首期建设

- React + TypeScript + Vite 前端。
- Python + FastAPI 后端。
- SQLite 唯一业务数据库，使用标准库 sqlite3。
- Python asyncio 进程内任务调度。
- Trending 日 / 周 / 月采集和历史快照。
- Stars 总榜独立采集、分片和完整性提示。
- 趋势总览、周期榜单、Stars 总榜、周期比较、推荐、兴趣和研究页面。
- Windows 启动脚本、日志、备份和恢复。

### 不纳入首期

PostgreSQL、Redis、Celery、Docker、微服务、多用户权限、远程公网访问、桌面壳和 AI 自动源码研究。

## 3. 阶段与验收

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| M0 | 工程基线与项目骨架 | React、FastAPI、本地开发代理和启动入口可用 |
| M1 | SQLite 数据底座 | 核心表、迁移、唯一约束、外键和测试通过 |
| M2 | Trending 采集 | 日 / 周 / 月真实采集、快照不可覆盖、历史可查 |
| M3 | Stars 总榜 | 手动 / 定时扫描、分片、去重、完整性提示 |
| M4 | 数据分析 | 总览、周期榜、历史选择、排名对比、项目详情 |
| M5 | 智能推荐 | 按 PRD 权重计算、缺失数据处理、历史批次可复现 |
| M6 | 兴趣与研究 | 收藏、研究状态、优先级、笔记持久化 |
| M7 | 本地交付 | Windows 启动、备份恢复、测试和使用文档通过 |

## 4. 当前已完成：M0 / M1 第一批

- 建立 React + TypeScript + Vite 工程。
- 建立左侧导航和页面骨架，保留单一周期榜单导航。
- 建立 FastAPI 应用、健康检查、首页概览和项目库读取 API。
- 建立 SQLite 连接工厂和初始 SQL 迁移。
- 建立项目、Trending、Stars、推荐、兴趣、研究、采集任务和系统设置相关表。
- 配置 SQLite WAL、外键、busy_timeout 和基础索引。
- 建立数据库迁移、幂等约束测试。
- 增加 Windows 本地启动脚本。

本阶段页面中的采集状态明确标记为等待接入；当前没有把模拟数据当成真实 GitHub 采集结果。

## 5. 后续详细任务

### M2 · Trending 采集

1. 实现 HTTPX GitHub 请求客户端。
2. 实现 BeautifulSoup 日 / 周 / 月解析器。
3. 为解析器建立 HTML Fixture 回归测试。
4. 按 github_repo_id 去重并 upsert 项目主档。
5. 每次采集写入独立 snapshot 与 items。
6. 实现手动触发、任务状态、失败重试和历史查询。
7. 实现 asyncio 定时调度，防止重复任务。

验收：日 / 周 / 月可以独立采集；历史快照不可覆盖；失败批次不标记成功。

### M3 · Stars 总榜

1. 接入 GitHub Search Repositories API。
2. 实现 Stars 降序和分页。
3. 实现 Stars 区间分片、结果合并和去重。
4. 记录分片结果、incomplete_results 和覆盖范围。
5. 实现手动刷新与定时刷新。
6. 遵守 GitHub API 限流头和退避策略。

验收：Stars 榜单独立于 Trending；部分分片失败时明确显示部分成功，不冒充全站完整榜单。

### M4 · 数据分析页面

- 总览统计、语言和主题分布。
- 周期榜单日 / 周 / 月切换和历史快照选择。
- Stars 总榜数据、更新时间和覆盖范围。
- 两个快照的新增、掉榜和排名变化。
- 项目详情、Stars 历史和周期表现。
- 采集任务列表、详情和日志。

验收：核心页面全部使用真实 SQLite 数据；查看历史快照不重新触发 GitHub 请求。

### M5 · 推荐引擎

严格遵循 PRD v0.5.1 第 16 节默认权重：

- Stars：30%
- 日榜：15%
- 周榜：30%
- 月榜：25%

实现百分位和上榜频率、有效样本门槛、缺失指标 N/A 与可用权重重新归一化、推荐理由、权重预设、算法版本及推荐历史。不得擅自改变评分口径。

验收：同一数据、算法版本和权重可复现同一结果；新计算批次不覆盖旧结果。

### M6 · 兴趣与研究

- 从榜单、推荐和项目详情标记 / 取消感兴趣。
- 感兴趣标记不自动创建研究记录。
- 项目可单独加入研究工作区，且不可重复加入。
- 支持待研究、研究中、已完成、暂缓。
- 支持优先级、研究目标、下一步行动、结论、笔记和标签。

验收：服务重启后收藏和研究数据仍然存在；取消兴趣不删除研究记录。

### M7 · 本地交付

- Windows 环境检查和启动入口。
- 日志轮转、异常提示和 Token 安全。
- SQLite 安全备份、恢复和 integrity_check。
- 完成前后端单元测试、API 集成测试和关键用户流程测试。
- 更新 README、安装教程和常见问题。

## 6. 测试策略

- 数据库：迁移幂等、唯一约束、外键、事务回滚、WAL。
- API：健康检查、分页、筛选、空状态和错误响应。
- Trending：HTML Fixture、字段缺失、解析异常和快照写入。
- Stars：限流、超时、分片失败、去重和 incomplete_results。
- 推荐：权重、窗口、样本不足、缺失值和结果复现。
- 前端：导航、加载、空状态、错误状态、历史选择和研究交互。
- 端到端：启动 → 采集 → 查历史 → 推荐 → 收藏 → 研究 → 重启 → 数据仍在。

## 7. Definition of Done

功能只有在需求编号明确、前端接入真实 API、后端逻辑完成、SQLite 持久化完成、异常状态完整、测试通过、文档更新并提交 GitHub 后，才标记为完成。

## 8. 下一迭代建议

完成 M0 / M1 验收后进入 M2：先实现 Trending 日 / 周 / 月采集器和历史快照链路，再开发 Stars 总榜采集。采集结果、快照完整性和错误信息优先于推荐算法和视觉细节。
